0004 シミュレータ
==================

# 発注

- Temper に LLM ベースのシミュレートシステムを作る。Agent 系とは独立に動き、モデルも自由に選べる。Agent と違ってバージョン管理はしない
- 処理は 3 ステップ
  1. プロンプト（シミュレート条件）と、戻り値の形式を同時に渡す
  2. LLM を 20 回実行し、経過と結果を得る
  3. 結果をマージする LLM が動き、結果を戻り値の形式にマージする
- 欲しい機能（ユーザーの言葉の要約）
  - 必要な場面が来たときに、シミュレータへのパラメーター（会話から抜き出すこともある）・戻り値の形式・シミュレータ名を引数にして、シミュレータを動かす機能
  - シミュレータのテスト実行機能
  - シミュレータの実行結果一覧（Agent が呼び出したものを含む）
  - シミュレータ自体のパラメーターを変更できる設定（GlobalSimulatingParameter など。名前は問わない）
- （1 回目）レビューして、何を実装するかを示し、不明点を質問する

# 作業ログ

- 既存の Agent 周り（agents/base・runner・llm・registry、assist/settings_chat、models・raw_models・config）、docs/specs、docs/decisions、worklog 0003 を確認
- シミュレータに当たる既存の実装は無いことを確認
- 実装案（未決）と不明点をチャットで提示
- （2 回目の回答）提案は全体的に採択。続けて次の回答を得た（ユーザーの言葉の要約）
  - シミュレータとして「n 回、最大の出目 m のサイコロを振った合計を返す」「最大の出目 m のサイコロ 1 回の出目を返す」「大吉 5・中吉 20・吉 50・凶 20・大凶 5 の割合で出すおみくじ」の 3 つを作ると考えてほしい
  - 必要な場面で、Agent（サブエージェントかもしれない）が自分で呼ぶかどうかを決める。少なくとも、AgentCore が決まった場面で呼ぶものではない。呼ばないこともある
  - 3 つともパラメーターは無いが、LLM の呼び出し回数（20 回）はグローバルな設定で変えたい。ほかは今のところ全部指定できるとする
  - パラメーターは「必須」「任意（既定はグローバルの指定）」「指定不可（グローバルでのみ指定）」に分ける
  - 実行時のパラメーター（グローバルでのみ指定するものを含む）と結果は必ず保存する。コードの保存は要らない
  - 経過とは、1 回ごとの LLM の呼び出しすべてのこと。シミュレート用の RAW を用意し、シミュレータごとに分ける
  - 戻り値の形式はシミュレータが決めるのが本来。LLM シミュレータだけが緩い。JSON スキーマ的なものでよく、最終結果は tool use で得る
  - 並列数・失敗の扱いなどはグローバルの設定に置く
  - テスト画面で実行するときは、グローバルの LLM シミュレート回数を 3 回にし、プロンプトも短めにする
- メモリ：このターンでの書き込みの許可を得て、worknote/ainotes/開発環境の注意.md に、画面で確かめるときの回数・プロンプトの注意を追記
- 回答を受けた解釈と不明点をチャットで提示（実装はまだ）
- （3 回目の回答。ユーザーの言葉の要約）
  - LLM 以外のシミュレータは、普通の乱数を使う。より高度なシミュレータを作るかもしれない。確定しているのは、今ではなく後で、ポーカー（NLH）のドローシミュレータを作りたいこと。n・m は呼び出しの引数
  - いつ使うべきかは Agent 側に定義する。シミュレータは呼ばれるだけ。必要なパラメーターが揃っているかだけはシミュレータが判断し、それを判断できる戻り値を返す。適切に呼べるかどうかは Agent 側の責任
  - チャット画面の表示用の内訳には、実行の呼び出しと結果だけを出す。中身はシミュレータ側に置く
  - テスト実行は「安く動作を確かめる」という意味。より安い方法があればそれでよい
  - 答えていないところを、まず教えてほしい
- 答えが出ていない点をチャットで提示（実装はまだ）
