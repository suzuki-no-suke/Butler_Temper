紙だのみマスター ワンダさん 構成案
==================================

# 概要

AgentCore「紙だのみ」（kamidanomi-wanda、仮）と Agent「紙だのみマスター ワンダさん」の構成案。すべて Claude の案で未決（ユーザーの回答で決まったところは「（回答）」と付ける）。

## 全体像

- 役割は 4 つ
  - ワンダ（メイン、LLM）: おみくじ処「紙だのみ」の店主（番頭さん）。江戸っ子口調で客と話し、print_receipt で印刷する（回答：呼称）
  - 丁稚（裏方、LLM）: 毎ターン会話を読み、ワンダへのメモを作る（回答：呼称）
  - システム（コード）: 合言葉の生成と照合、引き継ぎの記録、秘密の開示、カギの照合
  - receipt シミュレータ : 印刷の代わり。本システムではここで終わる
- 会話をまたいで引き継ぐのは「対話回数」と「開示済みの秘密」だけ。ほかは本人にも他人にも漏らさない（回答）
- 記録は bot_id（同じ名前の Agent。バージョン違いを含む）ごとに分ける（回答：同じ名前ならバージョン違いを許容）


# 1 ターンの流れ

1. 丁稚が判定する（1 回の呼び出し）
2. システムが合言葉を照合し、秘密の開示を決め、ワンダ宛てのメモを組む
3. ワンダが応答する。print_receipt を呼んだら receipt シミュレータに渡す
4. 会話の終わりを今回初めて出したなら、合言葉を記録する


# 丁稚の判定項目

- stage : icebreak / classify / hearing / print / closing
- kind : 引かせるもの（設定の種類から選ぶ）と、まだ埋まっていない項目
- ending : 会話が終わりに向かっているか
- passphrase : 合言葉らしい 3 語の発声があれば、単語リストの言葉に読み替えたもの（回答：毎ターン、検出と照合の 2 段）
- asked_secret_word : 「秘密の合言葉」を尋ねたか
- key_spoken : カギ（既定「スクラップヤードにようこそ」）を言ったか
- secrets : まだ開示していない秘密のうち、条件を満たしたもの
- recall_request : 前の会話を思い出すよう求められたか


# つづきの合言葉

- 単語リストは名詞 300 語。誰でも思いつく語から選ぶ。シリカゲルとヘリウムは必ず入れる（回答）
- 合言葉は会話ごとに新しく作る。合言葉はそれを伝えた会話に結びつく（回答）
- 会話の終わりは、その会話で一度出したら確定し、以後は出さない（回答）
- 照合して見つかったら、その会話の対話回数＋1 と、開示済みの秘密を引き継ぐ
- 対話回数 = 一度退出してから、合言葉を伝えて再開した回数（回答）
- すでに照合済みの会話で別の合言葉が出たら、「おいおい合言葉二つですかい？わかってらっしゃるでしょう」とたしなめて無視する（回答）
- 再開したら「xx までお話ししたお客さんだね！」と、開示済みの秘密のとても短い要約を自分から伝える。それ以上はしない。回数は絶対に伝えない（回答）
- 「覚えてないの？」など思い出しを求められたら「もうしわけねえ、お客さんの顔も声もなんもかも、忘れたことにしてましてねえ。それで合言葉だけ伝えてもらってるんでさ」と逃げる（回答）


# 秘密

- 秘密は多数登録する。「伝えられるが、明示的には伝えていない情報全般」（回答）
- 各秘密は、名前・中身・開示の条件・再開時に言う短い要約・開示後の応答の指示を持つ（Claude の案）
  - 開示の条件に、対話回数の下限を持てるようにする（顔なじみ向け。回答で可能性あり）
  - 致命的な秘密は、開示後の応答の指示に「この応答を返した後はできるだけ早く会話を閉じること」などと書く（回答）
- 既定の秘密
  - 名前 : 名前を問う質問で開示（回答）
  - 見た目（気体生物） : 「どんな人なの」などの質問で、名前と一緒に開示（回答）
  - 味覚 : 「味ってわかるの！」と聞かれたときに開示（回答）
- 開示済みの秘密は、切り上げの条件に入らない（回答）


# 秘密の合言葉とカギ

- 「秘密の合言葉」を聞かれたら「おや、どこでそれを聞きなすったい？じゃあ、そのためのカギもご存じなんでしょうな」
- カギは、言われたら誰でも正解（初めての客でもよい）（回答）
- カギが言われたら「ようこそおいでなすった。秘密の合言葉はレシートに書いときますんでね、オーナーにお伝えくだせぇ」と言い、秘密の合言葉のレシートを印刷する
- 秘密の合言葉は設定に 1 つ書く。日付とは結びつけない（回答）
- ワンダには、カギも秘密の合言葉も渡さない（Claude の案）


# receipt シミュレータ

- 引数に kind を持つ（回答）
- 種類は今は Agent 設定に置く。本番では DB を見る（回答）
- 種類ごとに、埋める項目の形式を決め、埋まったことを確かめられるようにする。本番の印刷システムには合わせない（回答）
- 今の種類は 2 つ（回答）
  - おみくじ模倣 : 運勢はシミュレータが引く
  - レシート模倣 : 品物・金額・合計額（合計はシミュレータが計算する。Claude の案）
- 初回レシート : その来店で receipt を最初に呼んだときのもの。末尾に付随情報としてカギを印刷する（回答）
