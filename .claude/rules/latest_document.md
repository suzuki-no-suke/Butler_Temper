最新版ドキュメント作成時ルール (Markdown)
=============================

設計資料としての最新版ドキュメントを作成・更新する場合の記載ルールについて述べる

とくに Markdown の場合について記載するが、その他の形式はこの限りではない。


# 過去の記録と最新の資料

資料は「過去の記録」と「最新の資料」に分けて扱う。過去の記録は、そのときに何が決まり何をしたかを後から追えるように、書いた後は変更しない。最新の資料は、今の決まりだけを読めば済むように、最新のものだけを残して整頓する。

## 細則

置き場所ごとに、どちらに当たるかを定める。

- 過去の記録 : docs/decisions、worknote/worklog
- 最新の資料 : docs/specs が代表
- 過去の記録は、絶対に書き換えない・消さない
  - 例) docs/decisions の決定が後で変わっても、その決定の記録は直さない。新しい決定は、新しい記録として足す
  - 例外 : 今の対話で書いている worklog は、その対話の中で書き足してよい（rules の worknote_folder.md）
- 最新の資料には、今の決まりだけを書く。古い決まり・以前の動作の説明は残さない
  - 例) 「以前はツールのやり取りを送らなかったが、今は送る」とは書かない。「送る」とだけ書き、経緯は決定経緯の参照に任せる
  - 決定経緯の参照（日付・所在）は消さない（`# 修正時の規則`）

(決定経緯 : 2026-10-31, worknote/worklog/0005-2026-10-31-SimulatorChatの結果埋め込み.md)


# 規則

- 全体の概要を必ず先頭に置く
- この資料を参照して作業を行う場合は、簡潔な手順も概要の後に置く
- その後に、個別の説明や詳細を置く
- 決定の経緯や参照すべき元資料がある場合は、項の末尾に記載する
  - 書き方は本資料の `参照資料記載規則` の書き方に従う
- 重要な規則と、細則を分けて記載すること
  - `# 設定置き場規則` と `## 詳細` や `## 細則`など
  - 重要な規則は簡潔な数行の文章を原則とする
  - 細則は箇条書きを原則とする


## Markdown規則

- 表形式はよっぽど合理的な理由がない限り使わず、箇条書きとすること
- AA による表記は行わず、箇条書きを原則とする
  - 複雑な図などは、mermaid や svg, 画像, html での出力を検討する



## 参照資料記載規則

ドキュメントのパスは現時点のもののみでよい

(決定経緯 : 2026-MM-DD, docs/xxxx/yyyy.md)
(手順書: docs/wwww/zzz.md)
(設計: docs/aaaa/bbbb.md)

原則として関連する項目の横におくこと。

全体の関連資料とする場合、資料の末尾にこの資料参照を配置し、なぜ・何が参照すべき内容であるかを併記すること

例
```
## (設計書: docs/..../フォルダ構造.md)

- アプリケーションごとに要請されるフォルダ配置およびプロジェクト内での作業用フォルダのルールについての原本

```

## 構成規則

- 先頭の `# 概要` は、1 行目でこの資料が何を定めるかを言い切る。続く `## 全体像` に要点を箇条書きで置く
  - 現状の制約や暫定事項は `(※ 現状…)` の形で添える
- 概要の次に `# 作業手順` を番号付き箇条書きで置く（この資料を見て作業する場合）
- 個別の項は「対象」ではなく「場面」で切る（例：`# 開発ローカルにおける運用`、`# サーバー内における運用`）
- 各項は次の三段で書く
  1. 規則の本文：数行の文章。何を守るためか（理由・意図）を必ず含める
  2. `## 細則`：箇条書き。まとまりごとに一言の前置き文を置いてよい
  3. `## さらなる例外細則`：推奨しない形・例外。必要なときだけ置く
- 細則には、判断に迷いやすいものに `例)` を添える（衝突例・禁止例を優先する）
- 禁止事項は強さを言葉で明示する（「絶対に〜しない」「〜してはならない」「推奨しない」を使い分ける）
- 順序の制約（「〜の前に」）と、具体的な値（日付の形式・権限の数値など）は省略せず細則に書く
- 運用上の心構えは、細則の入れ子の箇条書きとして書いてよい

## 参照の置き場所

- 決定経緯は、その決定が支えている項・細則の末尾に置く。決定ごとに日付を分ける
- 資料末尾の `# 関連資料` は、見出しを `## (種別: パス)` とし、その下に参照する理由を書く

## 修正時の規則

既存の資料を直すときも、本規則に従う。加えて次を守る。

- 構成が本規則に合っていなければ、内容を変えずに構成から合わせる
- 決まりの中身を変えた場合は、その項の末尾に新しい決定経緯（日付・経緯の所在）を足す。古い決定経緯は消さない
- 細則を直したら、概要・全体像・作業手順がまだ合っているかを見直す
- 同じ決まりが他の資料（設計書・手順書・tools/showcase4-adapt.md など）にもある場合は、食い違いを残さない。
  直さない場合は、食い違っている資料を作業ログに挙げる
  - 過去の記録（`# 過去の記録と最新の資料`）は直さない。過去の記録との食い違いは、作業ログに挙げなくてよい
- 未決・検討中の事項は書かない（TaskCard に置く）
- 誤字・重複・言い切れていない文（「だけが」の抜けなど）が無いかを、修正の最後に読み直す
