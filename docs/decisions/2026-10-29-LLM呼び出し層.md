2026-10-29 LLM 呼び出し層
==========================

# 概要

LLM を呼ぶ層を、BOT との会話（各社 SDK 直接）と AI 機能（PydanticAI）の二つに分けることを決めた経緯の記録。

## 決まったこと

- LLM を呼ぶ層が二つに分かれることを許容する（ユーザー回答）
- BOT との会話は、なるべく RAW な SDK 系統を使う（ユーザー回答）
- チャット改善などの AI 系は、PydanticAI を使って切り替えが容易なようにしておく（ユーザー回答）
- RAW データには、できれば現状の BOT のリビジョンが特定可能な情報も保存する。Git 連携を前提としてよい（ユーザー回答）


# 経緯

- ユーザーが PydanticAI を使うメリットの議論を希望した
- Claude が利点・欠点を挙げ、「BOT との会話は自前の薄い切り替え層で各社 SDK、設定変更チャットは PydanticAI」という案を出した
- ユーザーが二層に分かれることを許容し、理由を次のとおり示した
  - 自分がチャット相手とする LLM 系は、詳細なパラメーターや、メモリ内容など送信された内容を秘匿されない形で把握したい。LLM ごとの差が現れるのは明白なので、どれを使いどう返答されたかをなるべく多く把握するため、なるべく RAW な SDK 系統を使う
  - チャット改善などの AI 系は、裏側で動く LLM にこだわりは無く、目標を達成させるため、PydanticAI で切り替えを容易にしておく
- 議論の中でユーザーが、RAW データに BOT のリビジョンを特定できる情報を残したいと判明させた
  - 手段の候補としてユーザーが挙げたのは、ソースコードのそのままのバックアップ、バージョン更新の直前または直後のコミットなど。TOOL でやってもよいとした
