# 概要

アプリケーションの機能と利用の前提を、usernotes の主要仕様とユーザー回答から specs に書き出した経緯の記録。

## 決まったこと

- BOT 設定で変更できるのは、モデル以外の設定できるものすべて。モデルは変更させない（ユーザー回答）
- 設定変更チャットは別に存在する。画面に「編集中の設定」を持ち、チャットの変更案で更新され、「保存」で DB に保存して利用可能なバージョンにする（ユーザー回答）
- 回答へのコメントは GOOD / FINE / BAD + 自由記述。「全体にそうする」（ユーザー回答）
- RAW 用の DB を作り、リクエスト + レスポンスの JSON を保存する（ユーザー回答）
- ストリーミングはしない（ユーザー回答）
- 利用者は一人のみ。認証不要、ローカル動作のみ、合言葉等のガードも一切不要（ユーザー回答）
- 最初に作るのは、チャットと BOT の最低限の会話ができるところまで（ユーザー回答）
- tools に今置くものは無い（ユーザー回答）

# 追記 : 2026-10-29 モデル固定と Git リビジョン

## 決まったこと

- BOT ごとに利用するモデルを固定する。日付付きモデルがある場合（Anthropic は少なくともそう）は必ずそれを利用する（ユーザー回答）
- LLM API を切り替える際は、新しい構造の BOT として作る（ユーザー回答）
- RAW データに残したい「リビジョン」は、ソースコードの Git リビジョンのこと。設定の裏付けとなる動作を把握しておきたいという考えから。ソースコードが復元可能な形でバックアップされていればよい（ユーザー回答）

## 経緯

- Claude が TC0002 で「BOT のリビジョン」が BOT 設定のバージョンかソースコードかを不明点として挙げ、ユーザーが Git リビジョンの意味だと回答した
- 記録方法はユーザーが候補（コミット後にタグと DB への書き込みを必ず付ける等）を挙げたが未決
- 同一 API 内でのモデル変更の扱いは、ユーザーが Claude の見解を求めた。未決（TC0002）


# 追記 : 2026-10-29 ソースコードのバックアップ

## 決まったこと

- RAW 用の DB とは別に、Backend の「Agents 部分だけ」のバックアップ（DB、またはナマの ZIP・tarball）を置く（ユーザー回答）
- ハッシュが違う場合のみ追加保存する（ユーザー回答）
- 通信 RAW のところには、ハッシュをキーとして記録する（ユーザー回答）

## 経緯

- Claude がコミットフック・起動時の Git リビジョン記録を挙げた後、ユーザーが「ソースコードのコピーをそのまま DB に保存する手」を尋ねた
- Claude が「起動時にソースのハッシュを計算し、無ければアーカイブを保存、RAW からスナップショットを参照する」案を示した
- ユーザーが、RAW 用 DB とは別置き・Agents 部分のみ・ハッシュをキー、という形に決めた
- これにより、先の「Git リビジョンを保存する」要望は、ソースコードのバックアップで満たす形になった


# 追記 : 2026-10-29 バックアップの詳細

## 決まったこと

- バックアップには pyproject.toml と uv.lock を加える（ユーザー回答）
- ハッシュはファイルの中身で作る。パスと中身から並び順を固定して計算し、ZIP 自体のハッシュは使わない（Claude の案をユーザーが採用）
- data フォルダに ZIP で置く。ファイル名は `<ハッシュ>.zip`（Claude の案をユーザーが採用）
- PydanticAI はライブラリならいらない。自前で書く部分は必要（ユーザー回答）

# 追記 : 2026-10-29 TC0002 A〜E への回答

## 決まったこと

- 1 つの BOT が複数のモデルを持つ可能性は十分ある。DB の構造という考え方をせず、JSON などの設定で変更する考え方をする（ユーザー回答）
- 再実行のガードは「モデルが存在しなくなった場合に、それが意図せず実行されるのを止める」こと。同一名でしか使えない場合の変更は許容するしかない（ユーザー回答）
- コメントは、すべての回答にひとつずつ付ける。会話全体にも都度いくつも付けられる（ユーザー回答）
- BOT 設定の DB ファイルそのものを public_data に置く。JSON テキスト化を TOOL に追加する（ユーザー回答）
- data には「public_data に明示的に置くと決めたもの以外全部」を置く。現状 public_data は BOT 設定のみ（ユーザー回答）
- マイグレーションは Alembic（ユーザー回答）

## 経緯

- Claude が TC0002 の A〜E を質問し、ユーザーが回答した
- 「BOT 設定を JSON などの設定として持つ」の理由の一文は Claude の文案


# 追記 : 2026-10-29 実装前の確認への回答

## 決まったこと

- 一つの会話は、開始したときの BOT 設定のバージョンに固定する（ユーザー回答）
- メモリなど動作上の情報は、BOT が自発的に保存するものと設計する。RAW の保存は保険。前提情報が大きい場合は、その一部を BOT 自身が保存する（ユーザー回答）
- 最初に作る範囲に BOT 設定画面（バージョン管理を含む）と、チャット画面での BOT 選択を追加する（ユーザー回答）
- 分岐は不要。エラーが起きたらエラーを保存して止める（ユーザー回答）
- public_data の運用をやめ、すべて data に置く。公開したくなったらフォルダを作る（ユーザー回答）
- ローカルの設定ファイルは secrets/secrets.env。secrets フォルダ全体を無視する（ユーザー回答）
- 表示言語は日本語のみ（ユーザー回答）

## 経緯

- Claude が作り始める前の不明点 8 点を質問し、ユーザーが回答した。PostgreSQL 時の BOT 設定と public_data のコミットの件は、public_data の運用をやめたことで不要になった
