2026-10-29 フォルダ構成
========================

# 概要

リポジトリのルート直下と docs 配下のフォルダ構成、docs 配下のファイル名の付け方を決めた経緯の記録。

## 決まったこと

- ルート直下に apps / tools / docs を置く（ユーザー指示）
- apps には構築済みアプリケーションを置く。例として frontend / backend / migrate（ユーザー指示）
- tools にはアプリケーション動作の外側にあるものを置く。DB のバックアップ・リストア・デバッグ・設定のバリデーションなど、環境管理系が主（ユーザー指示）
- docs 配下に specs / knowhows / decisions を置き、確定事項を保管する（ユーザー指示）
  - specs : 確定した事項
  - knowhows : 外部から獲得した知識
  - decisions : 何かを決めた経緯などの記録
- フォルダ構成の規約は docs/specs に置く（ユーザー指示）
- worknote/usernotes は絶対にそのまま残す。そこから specs に改めて整頓して書き出すことはある（ユーザー指示）
- docs 配下のファイル名の付け方は Claude に一任された。Claude が次のとおり決めた
  - specs / knowhows : `(主題).md`
  - decisions : `YYYY-MM-DD-(主題).md`


# 経緯

- ユーザーがフォルダ構成（apps / tools / docs、docs 配下の specs / knowhows / decisions）を指示し、規約を docs/specs に置くよう依頼した
- Claude は用途・振り分け基準・命名規則が指示に無かったため、規約には書かず TaskCard（TC0001）に起票した
- ユーザーが apps / tools / specs / knowhows / decisions の用途を回答し、命名規則は「すきにして」と Claude に一任した。usernotes は移動しないことも併せて指示した
- 各項の規則本文にある「何を守るためか」の一文は、latest_document.md で必須のため Claude が文案を書いたもので、ユーザーの採用は受けていない
