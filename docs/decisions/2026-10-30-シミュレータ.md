2026-10-30 シミュレータ
=======================

# 概要

Agent から呼ぶシミュレータ（サイコロ・おみくじ・LLM シミュレータ）と、それを使う AgentCore を作った経緯の記録。

## 決まったこと（ユーザー指示）

- Agent 系とは独立に動くシミュレート系を作る。モデルは自由に選べ、バージョン管理はしない
- シミュレータ名・パラメーター・戻り値の形式を引数に、シミュレータを動かす。テスト実行・実行結果の一覧（Agent が呼んだものを含む）・全体の設定（GlobalSimulatingParameter など、名前は問わない）を持つ
- シミュレータは「n 回、最大の出目 m のサイコロを振った合計」「最大の出目 m のサイコロ 1 回の出目」「大吉 5・中吉 20・吉 50・凶 20・大凶 5 のおみくじ」と、LLM シミュレータ
  - LLM 以外は普通の乱数を使う。n・m は呼び出しの引数
  - 後で（今ではなく）ポーカー（NLH）のドローシミュレータを作りたい
- 呼ぶかどうかは、必要な場面で Agent（サブエージェントかもしれない）が自分で決める。AgentCore が決まった場面で呼ぶものではない
  - いつ使うかは Agent のプロンプトに定義し、AgentCore は tool use を検出する条件を定義する
  - シミュレータは呼ばれるだけ。必要なパラメーターが揃っているかだけを判断し、それを判断できる結果を返す。適切に呼べるかは Agent 側の責任
  - ツールの説明文は、シミュレータは短い固定の説明だけを持ち、使う条件は Agent のプロンプトに書く（Claude の案を採択）
- パラメーターは「必須」「任意（既定はグローバル）」「指定不可（グローバルのみ）」に分ける。実行時のパラメーター（グローバルのみのものを含む）と結果は必ず保存し、コードは保存しない
- 戻り値の形式はシミュレータが決める。LLM シミュレータだけは、JSON スキーマ的なものを受け取り、最終結果を tool use で得る
- LLM シミュレータは、同じプロンプトで別々に呼ぶ（ハルシネーションやばらつきを楽しむもの）。最後の 1 回は、全回の呼び出しをコンテキストに入れて全体の結果として処理する
  - 項目は、回数（任意、20 回）・モデル（任意、Sonnet 5.5）・プロンプト（必須）を基本とする
  - 経過とは 1 回ごとの LLM 呼び出しすべてのこと。シミュレート用の RAW を用意し、シミュレータごとに分ける
- 失敗の扱い : すべて失敗したときだけ全体を失敗にし、エラーとエラーの回数を伝える。LLM 呼び出しのエラーのときは、その回だけをそこで打ち切る。これは構造でありパラメーターにしない
- 並列数などはグローバル設定に置く
- シミュレータの定義を画面で編集する機能は要らない。LLM シミュレータのプロンプトは Agent 側が持つ。グローバル設定は履歴画面に一緒に出してよい
- チャット画面の表示用の内訳には、実行の呼び出しと結果だけを出す。中身はシミュレータ側に置く
- エージェント間対話でも使う。会話用エージェントでも一応使えるようにするが、今は使う会話用エージェントを足さない
- テスト実行（WebUI からの実行）は、安く動作を確かめるためのもの。呼び出し元が WebUI と分かるようにし、回数（シミュレーション全体を何回行うか。基本は 1 回）を指定できる
- シミュレータを使う Agent と AgentCore を足す。各ツールを呼び、唐突に「引いていかない？」と言い、明確に断られなければシミュレートする

## 追加の発注で決まったこと（ユーザー指示）

- シミュレータ設定の画面にも、グローバル設定を置く
- LLM シミュレータの MergeModel・MergeInstruction も指定できるようにする（任意、既定はグローバル設定）
- シミュレータ設定の画面に、シミュレータに渡す引数を提案する LLM を置く。固定のモデルでよい。提案はテスト実行の引数で、Agent 設定などに貼り付ければ LLM シミュレータなどにそのまま渡せるものとする。グローバル設定の値は提案しない
- テスト実行の入力欄には、任意の項目の既定値も含めて入れておく。提案する LLM は、既定値を含めて説明もする
- NLH のドローシミュレータを作る
  - 引数は、今のハンド（Villain は配列でポジションとハンド。X ならランダム）と今のボード。ベットのラウンドは無い
  - 指定の回数だけ繰り返し（Hero・Villain ともランダムならランダムで）、勝敗の回数と、Hero の勝利割合（勝利 / シミュレート回数）を返す。Villain が複数でも Hero の勝利で数える。引き分けは母数に含めるが勝利に含めない
  - 全部の結果を、何が何でも全部返す（量が多くなるのは仕方ない）
  - 回数の既定値はグローバル設定で 20 回。内部の上限は 1000 回で、設定値も 1000 以内にする
  - カードはランク 1 文字＋スート（s, c, d, h）の 2 文字。X は常に 2 枚分のランダム

## Claude が決めたこと（未採用）

- シミュレータを使う AgentCore は simulator-chat-sonnet（Sonnet 5.5）一つとした。ツールとして見せるシミュレータ（simulators）と、1 ターンにツールを呼ぶ往復の上限（max_tool_rounds、既定 4）を Agent 設定に置いた
- ツールのやり取りは次のターンに送らない（会話履歴に残るのは、メインの発言をつないだ文だけ）
- seed は、既に Agent がある DB にも、シミュレータを使う AgentCore の Agent が無ければ一つ作る
- グローバル設定の項目と既定値 : llm_runs 20、llm_model / llm_merge_model claude-sonnet-5-5、llm_run_max_tokens 2048、llm_merge_max_tokens 4096、llm_concurrency 5、llm_merge_instruction（固定の文）
- LLM シミュレータの回数は 1〜100、テスト実行の回数は 1〜20、サイコロの n は 1〜1000、m は 1〜1000000 に限った
- サイコロの合計が返すのは合計だけで、各回の出目は実行記録の内訳に置いた
- シミュレート用の RAW は、RAW 用の DB に simulationrawcall の表として置き、シミュレータ名の列で分けた
- まとめる回は tool_choice を auto にした（Sonnet 5.5 が強制の指定を受け付けなかったため。docs/knowhows/Claude5の強制ツール指定.md）

- 追加の発注のとき
  - グローバル設定は、シミュレーション履歴の画面にも残した
  - NLH のポジションは UTG, UTG+1, UTG+2, LJ, HJ, CO, BTN, SB, BB のどれかとし、Hero のポジションは任意（無しでもよい）にした。Villain は 1〜8 人
  - NLH のボードは 0・3・4・5 枚だけを受け付ける。1 回分の結果は、ハンド・ボード・役の種類（日本語）・勝者（Hero またはポジション）とした
  - シミュレータの名前は nlh_draw、表示名は「NLH ドローシミュレータ」とした
  - 提案のやり取りは保存せず、画面の中だけに持つ。提案の LLM は claude-sonnet-5-5
  - シミュレータを使う会話の AgentCore の既定のツールとプロンプトに、nlh_draw を足した（既に保存した Agent 設定は変わらない）
  - テスト実行の結果の枠は、高さを決めてスクロールさせた
