2026-10-29 Agent 方式
=====================

# 概要

BOT を「プロバイダー + モデル + 設定」ではなく「コードで定義した Agent + 設定 JSON」として作る方式に変えた経緯の記録。

## 決まったこと

- プロバイダーという考え方をせず、BotAgent を都度作るという考え方をする（ユーザー指示）
- Agent の設定は一つの JSON で全部記述する。デフォルトの設定をサンプルとして与える（ユーザー指示）
- BOT 設定画面には、名前、採用する Agent、Agent の解説（モデル名など）、Agent の全設定 JSON（新規作成時はデフォルト設定）を置く（ユーザー指示）
- 現在設定が残っている Agent + 設定の一覧を置き、選択したら編集できるようにする（ユーザー指示）
- 用意する Agent（ユーザー指示）
  - 2 BOT で、Opus 5.5（メイン）と Haiku 5.5（サブ）を使い、5000 文字（トークンではない）までの会話と、それ以前の会話の要約（メモリ）を会話コンテキストに持ち、一定の条件を満たす会話がされたら秘密情報をサブが開示する二層構造
  - Fable / Opus / Sonnet / Haiku の最新版と、システムプロンプトだけ設定して会話できる BOT。維持するコンテキスト長は Claude に一任

## Claude が決めたこと（未採用の案）

- 二層構造の動き方
  - メインは秘密を知らない。サブが毎ターン、メインの応答の後に開示条件を判定し、満たせばサブ自身の発言として開示する
  - 判定と開示の発言は、サブの 1 回の呼び出しで JSON として返させる
  - 既定では一度開示したら以後は判定しない（disclose_once）
  - 要約（メモリ）もサブが作る
  - 次のターンに渡す会話履歴はメインの発言だけ
- シンプル会話の維持するコンテキスト長は、直近 40000 文字（要約なし）
- モデル ID は claude-fable-5-1 / claude-opus-5-5 / claude-sonnet-5-5 / claude-haiku-5-5。日付付きの ID があるかは確かめていない
- 既定の設定の中身（執事と影の管理人の設定、秘密・開示条件の例文）
- BOT が一つも無いとき、各 Agent の既定の設定で BOT を作る（npm run dev の中で実行）
- BOT の名前は変更でき、バージョン管理しない
- 設定の保存時に、Agent の設定の形に合っているか確かめる（知らない項目はエラー）

## 経緯

- ユーザーがローカルで起動したところ BOT が無かったことから、作ってほしい BOT の例と、BOT 設定画面の形が示された
- それまでの「BOT ごとにプロバイダーとモデルを JSON で持つ」形は、この方式に置き換えた。旧方式の DB の列（bot.provider / bot.models / rawcall.provider / rawcall.model）はマイグレーションで削除した
