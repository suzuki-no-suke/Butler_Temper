2026-10-29 呼称の整頓
=====================

# 概要

Agent 関連の呼称を整頓し、プロジェクト辞書（docs/specs/プロジェクト辞書.md）に定めた経緯の記録。

## 決まったこと

- 仕様一覧にプロジェクト辞書を追加する。何となく付けたところは一旦記載せず、まずは BOT 関連のみ（ユーザー指示）
- それまで Agent と呼んでいたものを AgentCore、BOT と呼んでいたものを Agent と変更し、記載も統一する（ユーザー指示）
- 定義（ユーザー指示）
  - LLM API : 環境問わず、LLM としての応答を行う API 系
  - AgentCore : モデルの選択と処理の流れ
  - Agent 設定 : AgentCore に対して適用する設定情報
  - Agent : AgentCore + Agent 設定によって作られる、対話を行う相手
  - Agent のバージョン : 同じ名前だが、設定が異なる複数の Agent を指して言う。古いもののバージョンが古い
  - Agent のフォーク : ある Agent から、名前を変更した Agent を作成すること。AgentCore は同じ。設定の一部または全部を引き継いでいる
- 一般的な用法（特にバージョン・フォーク）とは若干異なるので注意する（ユーザー指示）
- 矛盾していなければ、ドキュメントと UI 表示を変更する（ユーザー指示）

## Claude が決めたこと（未採用の案）

- 変更の範囲は、docs/specs の資料、README.md、worknote/artifacts/v1_localtask.md、画面の文言、API が返すメッセージ、設定変更チャットで LLM に渡す説明文
- docs/decisions の過去の記録と worklog は、当時の呼称のまま残す（記録を書き換えないため）
- コード・DB・API の名前（bot テーブル、agent_id、/api/bots、/api/agents など）は変えていない
- docs/specs/Agent一覧.md を docs/specs/AgentCore一覧.md に名前を変えた
- 辞書のバージョン・フォークの項に、一般的な用法との違いを一行ずつ添えた

## 経緯

- 定義を現状の仕様・実装に当てたところ、呼称どうしの矛盾は無かった。次の二点は、実装が定義から外れうる場面として報告した（実装は変えていない）
  - 設定を変えずに保存しても新しいバージョンになる（定義では「設定が異なる」）
  - 「既定の Agent 設定を読み込む」の後に名前を変えて保存すると、元の Agent の設定を何も引き継がないフォークになる（定義では「一部または全部を引き継いでいる」）
