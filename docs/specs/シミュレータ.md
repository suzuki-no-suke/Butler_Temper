シミュレータ
============

# 概要

本資料は、Agent から呼ばれて結果を返すシミュレータの仕組み・項目・記録・画面を定める。

## 全体像

- シミュレータは、呼ばれたときの引数を受けて結果を返すだけのもの。Agent とは独立して動き、バージョン管理はしない
- 用意しているシミュレータは次の四つ。すべてコード（apps/backend/src/bt_backend/simulators）で定義する
  - おみくじ（omikuji） : 大吉 5・中吉 20・吉 50・凶 20・大凶 5 の割合で吉凶を返す
  - サイコロ（dice） : 出目の最大が m のサイコロを 1 回振り、出目を返す
  - サイコロの合計（dice_sum） : 出目の最大が m のサイコロを n 回振り、合計を返す
  - LLM シミュレータ（llm） : 同じプロンプトで LLM を別々に何回か呼び、最後の 1 回で全体の結果にまとめる
- いつ呼ぶかは Agent が決める。シミュレータは、引数が揃っているかだけを判断する
- 項目は「必須」「任意（既定はグローバル設定）」「指定不可（グローバル設定でのみ決める）」に分ける
- 実行のたびに、実際に使った値（グローバル設定の値を含む）と結果を実行記録に残す。シミュレータのソースは残さない
- 画面は「シミュレータ」（一覧とテスト実行）と「シミュレーション履歴」（実行記録とグローバル設定）の二つ


# 作業手順

1. シミュレータを足すときは、simulators に Simulator を継承したクラスを作り、simulators/__init__.py の一覧に登録する
2. 呼ぶ側が渡す引数は SimulatorArgs を継承したモデルで定義する。既定値の無い項目が必須、既定値のある項目が任意になる
3. 任意の項目の既定をグローバル設定から取るときは global_defaults に、指定不可の項目は global_only に、グローバル設定の項目名を書く
4. グローバル設定の項目を足すときは、GlobalSimulationSettings に既定値と説明（description）を付けて足す
5. 本資料に書き足す


# Agent からの呼び出し

Agent の LLM には、シミュレータをツール（tool use）として見せる。呼ぶかどうか・いつ呼ぶかは Agent の側の責任であり、条件は Agent 設定（プロンプト）に書く。シミュレータを Agent から独立させ、呼び方の工夫を Agent の調整として扱うためである。

## 細則

AgentCore とシミュレータの受け渡しは次のとおり。

- TurnContext.simulators（会話用エージェントは SpeakContext.simulators）に、使えるシミュレータの一覧（tools）と呼び出し口（call）が入る
  - AgentCore は、応答の tool_use を検出して call を呼び、結果を tool_result として返す
- シミュレータが持つのは、名前・短い固定の説明・引数の型（JSON Schema）だけ。いつ使うかの説明は持たない
- 呼ぶと必ず実行記録が残る。返る結果は次の形
  - 成功 : `{"ok": true, "result": 結果}`
  - 引数が足りない・合わない : `{"ok": false, "error": 理由, "missing": [足りない項目]}`（実行はしない）
  - 失敗 : `{"ok": false, "error": 理由}`
  - LLM シミュレータでは、どの場合も error_count（LLM 呼び出しのエラーの回数）を添える
- 指定不可の項目を引数に渡すと、引数が合わないものとして扱う
- チャット・エージェント間対話の表示用の内訳には、シミュレータの呼び出しと結果だけを出す（speaker が simulation）。中身は実行記録で見る
- 会話用エージェントも、仕組みとしてはシミュレータを呼べる。現状、呼ぶ会話用エージェントは無い

# LLM シミュレータ

条件のはっきりしないプロンプトで LLM に何回か別々にシミュレートさせ、回ごとのばらつきやハルシネーションを含めて、全体の結果にまとめる。

## 細則

項目は次のとおり。

- 必須 : prompt（シミュレートの条件。各回にそのまま送る）
- 任意 : runs（別々に呼ぶ回数。既定はグローバル設定の llm_runs）、model（各回のモデル。既定はグローバル設定の llm_model）、output_schema（全体の結果の形式。type が object の JSON Schema。既定は `{"result": 文章}` の形）
- 指定不可 : llm_merge_model、llm_merge_instruction、llm_run_max_tokens、llm_merge_max_tokens、llm_concurrency

進め方は次のとおり。

- 同じプロンプトで、別々に runs 回呼ぶ（会話の文脈は持たせない）。同時に呼ぶのは llm_concurrency 個まで
- 最後の 1 回で、指示（llm_merge_instruction）・条件・各回の出力をすべてコンテキストに入れ、submit_result ツールで output_schema の形の結果を得る
  - tool_choice は auto とし、指示でツールを呼ばせる。Claude 5 系の一部はツールを強制する指定を受け付けないため（docs/knowhows/Claude5の強制ツール指定.md）
  - ツールを呼ばなかったときは失敗とする
- サンプリングの値（temperature など）は送らない
- LLM 呼び出しのエラーは、その回だけをやり直さずに打ち切り、エラーとして数える。これは構造であり、項目にはしない
- すべての回が失敗したとき、または最後の 1 回が失敗したときだけ、全体を失敗とする

(決定経緯 : 2026-10-30, docs/decisions/2026-10-30-シミュレータ.md)


# 記録とグローバル設定

シミュレータはバージョン管理をしない代わりに、実行のたびに使った値をすべて残す。後からグローバル設定を変えても、過去の結果がどの値で出たかを追えるようにするためである。

## 細則

- 実行記録（通常の DB の simulationrun）に、シミュレータ名・呼び出し元・渡された引数・実行に使った値のすべて・状態（成功 / 失敗 / 引数が合わない）・結果・内訳・エラーの回数を置く
  - 呼び出し元は、チャット（conversation）・エージェント間対話（dialogue）・WebUI のテスト実行（webui）のどれか
  - チャット・エージェント間対話から呼ばれたときは、会話（対話）と、そのターンで保存した発言に結びつける。呼んだ AgentCore も残す
  - 内訳には、サイコロの合計の各回の出目、LLM シミュレータの各回の出力を置く
- シミュレート用の RAW（RAW 用の DB の simulationrawcall）に、LLM 呼び出しを 1 回分ずつ置く。シミュレータ名を持たせ、シミュレータごとに分けて見られるようにする
  - 各回は run-1, run-2 …、最後の 1 回は merge というラベルで置く
- グローバル設定（通常の DB の simulationsettingsrow、1 行だけ）は、画面から JSON で変える。履歴は持たない
  - 知らない項目・範囲外の値は保存できない

(決定経緯 : 2026-10-30, docs/decisions/2026-10-30-シミュレータ.md)


# 画面

シミュレータの画面は、Agent・エージェント間対話のメニューの後ろに区切りを置いて並べる。

## 細則

- シミュレータ : シミュレータの一覧と、項目（必須・任意・指定不可）の説明を出す。引数を JSON で書いてテスト実行できる
  - テスト実行は、安く動作を確かめるためのもの。呼び出し元は WebUI（テスト実行）として記録する
  - 実行する回数は、シミュレーション全体を続けて何回行うか（既定 1。LLM シミュレータの内側の回数ではない）
- シミュレーション履歴 : 実行記録の一覧を、シミュレータと呼び出し元で絞り込める。Agent が呼んだもの・テスト実行の両方が並ぶ
  - 一つを開くと、結果・引数・実行に使った値・内訳・シミュレート用の RAW を見られる
  - グローバル設定は、このページに折り畳みで置く

(決定経緯 : 2026-10-30, docs/decisions/2026-10-30-シミュレータ.md)
