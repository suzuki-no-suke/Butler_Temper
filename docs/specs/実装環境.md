実装環境
========

# 概要

本資料は、アプリケーションの実装に用いる言語・フレームワーク・ライブラリ管理・DB・LLM API・テスト、およびデータ・設定・機密情報の置き場所を定める。

## 全体像

- 採用理由は、いままで使っていて、現状もっとも理解が早いスタックであるため
- Frontend : TypeScript + React + React Router（HashRouter）、パッケージ管理は npm、ビルドは Vite
- Backend : Python 3.14 + FastAPI、ライブラリ管理は uv、ORM は SQLModel
- DB : SQLite（PostgreSQL にも対応させる）。RAW 用の DB を別に作る
- LLM API : Agent がそれぞれ使う。まずは Anthropic を用い、最低限 OpenAI / Gemini / OpenRouter も使えるようにする
- ライブラリ・Node のバージョンは指定しない（原則最新を使う）
- 配信 : Frontend は Apache などで静的配信する。FastAPI は Frontend を配信しない
- データはすべてルート直下の data（コミットしない）に置く。機密情報は secrets に置く
- 設定は環境変数で渡す
- LLM を呼ぶ層は二つに分ける
  - BOT との会話 : 各社の SDK を直接呼ぶ
  - チャット改善などの AI 機能 : PydanticAI を用いる
- テスト・静的チェックを行う


# 作業手順

1. Frontend は apps/frontend、Backend は apps/backend、マイグレーションは apps/migrate に置く
2. Python のライブラリは uv、Frontend のライブラリは npm で追加する
3. ローカルでは secrets/secrets.env に設定と機密情報を書いて起動する
4. 変更後は `# テスト・静的チェック` の細則にあるチェックを通す

# Agents モジュール

LLM の呼び出しに関するソースは、Backend の Agents のモジュールフォルダにまとめて置く。通信時のソースコードのバックアップは Agents のモジュールフォルダ全体を対象とするので、フローに関わるソースが Agents の外にあると、その変更が記録されないためである。

## 細則

- LLM の呼び出しに関連するソースは、Agents のモジュールフォルダに置く
  - 例) Anthropic SDK を呼ぶ共通パーツを Agents の外に置いてはならない
- Agents を呼び出す側とのインターフェイスは、原則疎にしておく
- 対話用 LLM（各社 SDK 直接）と PydanticAI 側（AI 機能）は別口とし、無理に共通化しない

(決定経緯 : 2026-10-29, docs/decisions/2026-10-29-アプリケーション仕様.md)


# DB

DB は SQLite を用い、PostgreSQL にも対応させる。ORM には SQLModel を用いる。ローカルでは手軽な SQLite で動かしつつ、PostgreSQL に移れる余地を残すためである。

## 細則

- DB : SQLite
  - PostgreSQL にも対応させる
- ORM : SQLModel
- LLM API の RAW 入力・出力を保存する RAW 用の DB を、通常の DB とは別に作る
- マイグレーションには Alembic を用いる
  - リモートでは Python で動かす
  - ローカルでは `npm run migrate` から Python（Alembic）を呼ぶ

(決定経緯 : 2026-10-29, docs/decisions/2026-10-29-実装環境.md)


# LLM API

LLM API は Agent ごとに、必要なものを使う前提で作る。まずは Anthropic の API を用いる。LLM を呼ぶ層は、BOT との会話と、チャット改善などの AI 機能とで二つに分ける。

BOT との会話では、詳細なパラメーターや、メモリ内容など実際に送信された内容を秘匿されない形で把握したい。また LLM ごとに差が現れるのは明白なので、どれを使いどう返答されたかをなるべく多く把握するために、なるべく RAW な SDK を使う。一方、チャット改善などの AI 機能は裏側で動く LLM にこだわりが無く、目標を達成できればよいので、切り替えが容易な PydanticAI を使う。

## 細則

対応する LLM API は次のとおり。

- 最初に用いる LLM API : Anthropic
- 最低限、次の LLM API も使えるようにしておく
  - OpenAI
  - Gemini
  - OpenRouter
- 使う LLM API は Agent ごとに異なりうる。一つの Agent が複数の LLM API を使ってもよい
- Agent は apps/backend/src/bt_backend/agents/llm.py の LlmSession を通して呼ぶ。呼び出しごとの HTTP の中身が、役割（label）付きで記録される

LLM を呼ぶ層は次の二つに分ける。二つに分かれることは許容する。

- BOT との会話（利用者がチャット相手とする LLM）
  - 各社の SDK を直接呼ぶ（Anthropic SDK / OpenAI SDK / Gemini SDK など）
  - 送信内容・パラメーターを、ライブラリによる付け足しや隠蔽なしに把握できるようにする
- チャット改善・設定変更チャットなどの AI 機能
  - PydanticAI を用いる
  - 裏側で動く LLM は容易に切り替えられるようにする

# データ・設定・機密情報の置き場所

アプリケーションのデータは、すべてコミットしない data に置く。公開したいデータが出てきたら、そのときに別のフォルダを作る。設定と機密情報は環境変数で渡す。

## 細則

データの置き場所は次のとおり。

- data : リポジトリにコミットしないデータの保存場所
  - .gitignore に記載する
  - アプリケーションのデータはすべて data に置く
  - 既定のファイルは次のとおり
    - app.db : 通常の DB（BOT 設定・会話）
    - raw.db : RAW 用の DB
    - agent_snapshots/<ハッシュ>.zip : Agents のソースのバックアップ
  - 例) BOT 設定、会話・発言、コメント・評価、RAW 用の DB、Agents のソースのバックアップ、設定変更チャットの履歴
- アプリケーションは、data の書き込み先を設定で変更できるようにする
- 公開したいデータが出てきたら、そのときに別のフォルダを作る
  - 作るときは、data とは必ず別のフォルダにしなければならない

設定と機密情報は次のとおり。

- 設定は環境変数で渡す
  - 最終的には systemd から環境変数を読み込ませる
  - ローカルでは secrets/secrets.env を用いる
- 機密情報は secrets フォルダに置く
  - secrets フォルダは全体を .gitignore で無視する（記載済み）

(決定経緯 : 2026-10-29, docs/decisions/2026-10-29-実装環境.md)

- テスト : Vitest
