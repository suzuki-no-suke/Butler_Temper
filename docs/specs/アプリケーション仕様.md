アプリケーション仕様
====================

# 概要

本資料は、チャットボットのプロンプトによる展開・性格表出について調査・調整を行うアプリケーションの機能と、利用の前提を定める。

## 全体像

- 利用者は一人のみ。ローカル動作のみを想定し、認証・合言葉などのガードは一切設けない
- UI は次の三つ
  - チャットを入力すると BOT が応答する UI（対話専用。回答にコメント・評価を残せる）
  - BOT 設定を変更する UI（設定変更チャット・設定のバージョニングを含む）
  - 対話履歴を振り返り、設定等を確認する UI
- LLM API へのリクエストとレスポンスの JSON は、RAW 用の DB に保存する
- 応答はストリーミングしない
- 画面の表示言語は日本語のみ
- 最初に作るのは、チャットと BOT の最低限の会話、BOT 設定画面（バージョン管理を含む）、チャット画面での BOT 選択
- 用意する Agent は docs/specs/Agent一覧.md に記す


# 作業手順

1. 最初の実装では `# 最初に作る範囲` の範囲だけを作る
2. 機能を足すときは、本資料の該当する項の細則に合わせる
3. 本資料に無い機能が必要になったら、作る前に TaskCard に起票する


# 利用の前提

利用者は一人のみで、ローカルでのみ動作させる。調査・調整用の道具であり、利用者を区別する必要が無いためである。

## 細則

- 認証は設けない
- 合言葉などのガードも一切設けない
- 応答はストリーミングしない
- 画面の表示言語は日本語のみ

# チャット UI

チャットを入力すると BOT が応答する。対話専用とし、回答にはコメント・評価を残せるようにする。

## 細則

- 入力はテキストの対話のみ
  - 画像入力・音声入力・ファイル入力はしない
- 回答へのコメント・評価は、評価 + 自由記述とする
  - 評価は GOOD / FINE / BAD の三段階
- チャット画面で、会話する BOT を選択する
- 一つの会話は、開始したときの BOT 設定のバージョンに固定する
- 会話は分岐させない
- LLM API の呼び出しでエラーが起きたら、エラーを保存して止める
- BOT の回答には、一つずつ、コメント・評価を一つ付けられる
- 会話全体には、都度いくつでもコメントを付けられる

# BOT 設定 UI

BOT は「名前」「採用する Agent」「Agent の全設定 JSON」からなる。Agent は、使うモデルと処理の流れをコードで定義したもので、BOT はその都度 Agent を選んで作る。プロバイダー（LLM API の提供元）という単位では考えない。設定はバージョンとして保存し、設定変更チャットで変更案を作れるようにする。

## 細則

Agent の扱いは次のとおり。

- Agent はコードで定義する。使うモデル（複数可）と処理の流れは Agent ごとに固定する
  - モデルを変えたい場合は、別の Agent を作る
- Agent の設定は、一つの JSON で全部記述する。モデル以外の、設定できるものすべてを含む
  - 設定項目の追加・変更で DB の構造を変えなくて済むようにするためである
- Agent ごとに既定の設定を持ち、設定のサンプルとして示す
- 設定を保存するときは、Agent の設定の形に合っているかを確かめる。合っていなければ保存しない
  - 例) 知らない項目（書き間違い）があると保存できない
- 日付付きのモデル ID がある場合は、必ず日付付きのものを利用する
  - 例) Anthropic は少なくとも日付付きのモデル ID がある
- モデルが存在しなくなった場合は、その BOT が意図せず実行されるのを止める
  - 提供元が同一名のまま中身を変えた場合は、検知できないため許容する

BOT 設定画面に表示するものは次のとおり。

- 設定済みの BOT（Agent + 設定）の一覧。選ぶと編集できる
- 名前（変更できる。バージョン管理はしない）
- 採用する Agent（作成後は変更できない）
- Agent の解説（モデル名などを含む）
- Agent の全設定 JSON（新規作成時は Agent の既定の設定）

編集と保存の流れは次のとおり。

- 画面には「編集中の設定」を保持する
- 設定変更チャットは BOT との会話とは別に存在する
  - 設定変更チャットの LLM とプロンプトはコードに書き、設定画面からは変更できない
- 設定変更チャットで変更案ができたら、画面の「編集中の設定」が更新される
  - この時点では DB に保存しない
- 利用者が「保存」したときに、編集中の設定を DB に保存し、利用可能なバージョンにする
- BOT 設定は全バージョンを data に残す（docs/specs/実装環境.md）
- BOT 設定を JSON テキストに書き出す道具を tools に置く

BOT 自身が保存する情報は次のとおり。

- メモリなど、動作上の情報は BOT が自発的に保存するものとして設計する
- 前提情報が大きい場合は、その一部を BOT 自身が保存する
- RAW の保存は、これらに対する保険と位置づける

# 対話履歴 UI

チャットに関するすべての情報を保持し、閲覧できるようにする。調査のために、いつ・どの設定で・何を送り・何が返ったかを後から追えるようにするためである。

## 細則

- 閲覧できる情報は次のとおり
  - 会話履歴
  - 設定値
  - すべての RAW 入力・出力
  - AI 状況（LLM のモデル・バージョンや利用日付などの情報）
- RAW 入力・出力は、RAW 用の DB に保存する
  - 保存するのは LLM API へのリクエストとレスポンスの JSON
- 通信時の Backend のソースコードを、復元可能な形でバックアップする
  - どういう構造でフローしているかを後から把握できるようにするためである
  - 動作をそのまま再現・復元することは目的としない
  - バックアップの対象は次のとおり
    - Backend の Agents のモジュールフォルダ全体
      - 関連するソースは Agents のフォルダに置く（docs/specs/実装環境.md）
      - 自前で書いた AI 機能（PydanticAI を使う側）のコードも含める
      - ライブラリ自体（PydanticAI など）は含めない
      - import をたどって対象を決めることはしない
    - pyproject.toml と uv.lock（ライブラリのバージョンを残すため）
  - バックアップは RAW 用の DB とは別に、data フォルダに ZIP で置く
    - ファイル名は `<ハッシュ>.zip` とする
  - ハッシュは、ファイルのパスと中身から、並び順を固定して計算する
    - ZIP 自体のハッシュは使わない（作成時刻などで変わるため）
    - `__pycache__` などの生成物は含めない
  - ハッシュが既存のものと異なる場合のみ、追加で保存する
  - RAW 用の DB の通信記録には、そのハッシュをキーとして記録する
