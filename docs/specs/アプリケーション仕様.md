アプリケーション仕様
====================

# 概要

本資料は、チャットボットのプロンプトによる展開・性格表出について調査・調整を行うアプリケーションの機能と、利用の前提を定める。

## 全体像

- 利用者は一人のみ。ローカル動作のみを想定し、認証・合言葉などのガードは一切設けない
- UI は次の三つ
  - チャットを入力すると Agent が応答する UI（対話専用。回答にコメント・評価を残せる）
  - Agent 設定を変更する UI（設定変更チャット・設定のバージョニングを含む）
  - 対話履歴を振り返り、設定等を確認する UI
- これとは別に、会話用エージェントが Agent と会話するエージェント間対話の UI を持つ（`# エージェント間対話`）
  - 会話用エージェントの設定・テンプレート・エージェント間対話・その履歴の四つの画面を、Agent の画面とは別のメニューに置く
- 会話の最初から、または会話・エージェント間対話の途中から、同じ入力への応答（候補）を何パターンも作り、一つを採用して新しい会話として続ける並行会話を持つ（`# 並行会話`）。並行会話と並行会話設定の二つの画面を、別のメニューに置く
- Agent が自分で呼ぶシミュレータ（サイコロ・おみくじ・LLM シミュレータ）を持つ。シミュレータと、その実行記録の二つの画面を、さらに別のメニューに置く（docs/specs/シミュレータ.md）
- LLM API へのリクエストとレスポンスの JSON は、RAW 用の DB に保存する
- 応答はストリーミングしない
- 画面の表示言語は日本語のみ
- 最初に作るのは、チャットと Agent の最低限の会話、Agent 設定画面（バージョン管理を含む）、チャット画面での Agent 選択
- 用意する AgentCore は docs/specs/AgentCore一覧.md に記す


# 作業手順

1. 最初の実装では `# 最初に作る範囲` の範囲だけを作る
2. 機能を足すときは、本資料の該当する項の細則に合わせる
3. 本資料に無い機能が必要になったら、作る前に TaskCard に起票する


# 利用の前提

利用者は一人のみで、ローカルでのみ動作させる。調査・調整用の道具であり、利用者を区別する必要が無いためである。

## 細則

- 認証は設けない
- 合言葉などのガードも一切設けない
- 応答はストリーミングしない
- 画面の表示言語は日本語のみ

# チャット UI

チャットを入力すると Agent が応答する。対話専用とし、回答にはコメント・評価を残せるようにする。

## 細則

- 入力はテキストの対話のみ
  - 画像入力・音声入力・ファイル入力はしない
- 回答へのコメント・評価は、評価 + 自由記述とする
  - 評価は GOOD / FINE / BAD の三段階
- チャット画面で、会話する Agent を選択する
- 一つの会話は、開始したときの Agent のバージョンに固定する
- 会話は分岐させない
- LLM API の呼び出しでエラーが起きたら、エラーを保存して止める
- Agent の回答には、一つずつ、コメント・評価を一つ付けられる
  - 評価は必須、コメントは任意。付け直すと上書きする。消せる
- 会話全体には、都度いくつでもコメントを付けられる
  - 評価とコメントのどちらかがあればよい。消せる
- 評価・コメントは、エラーで止まった会話にも付けられる
- 会話画面の右側に、折り畳みの「RAW パラメーター」欄を置く。会話中も、過去の会話を開いたときも使える
  - 選んだ発言（既定は RAW のある最新の発言）について、Agent の状態（Agent が残した記録）、表示用の内訳、RAW（LLM とのやり取りごとの役割・URL・状態・時刻・リクエスト・レスポンス）、ソースのハッシュ、エラーを表示する
  - 選んだ発言が Agent の回答なら、その回答への評価・コメントも表示する
  - 送信すると、最新のターンの表示に切り替わる
- 会話画面の下に、ここまでに回答へ付けた評価とコメントの一覧（評価ごとの件数を含む）を、会話全体へのコメントと並べて表示する
  - 一覧から、その回答を RAW パラメーター欄で開ける
  - 開いているかどうかは、ブラウザに覚えさせる

# Agent 設定 UI

Agent は「名前」「採用する AgentCore」「Agent 設定（JSON）」からなる。AgentCore は、モデルの選択と処理の流れをコードで定義したもので、Agent はその都度 AgentCore を選んで作る。プロバイダー（LLM API の提供元）という単位では考えない。設定はバージョンとして保存し、設定変更チャットで変更案を作れるようにする。

## 細則

AgentCore の扱いは次のとおり。

- AgentCore はコードで定義する。使うモデル（複数可）と処理の流れは AgentCore ごとに固定する
  - モデルを変えたい場合は、別の AgentCore を作る
- Agent 設定は、一つの JSON で全部記述する。モデル以外の、設定できるものすべてを含む
  - 設定項目の追加・変更で DB の構造を変えなくて済むようにするためである
- AgentCore ごとに既定の Agent 設定を持ち、設定のサンプルとして示す
- 設定を保存するときは、AgentCore が受け付ける Agent 設定の形に合っているかを確かめる。合っていなければ保存しない
  - 例) 知らない項目（書き間違い）があると保存できない
- 日付付きのモデル ID がある場合は、必ず日付付きのものを利用する
  - Anthropic の 4.6 世代以降は日付付きの ID が無く、日付の無い ID 自体が固定のスナップショットなので、それを使う（docs/knowhows/AnthropicのモデルID.md）
- モデルが存在しなくなった場合は、その Agent が意図せず実行されるのを止める
  - 提供元が同一名のまま中身を変えた場合は、検知できないため許容する

Agent 設定画面に表示するものは次のとおり。

- 設定済みの Agent（AgentCore + Agent 設定）の一覧。選ぶと編集できる
- 名前
- 採用する AgentCore（作成後は変更できない）
- AgentCore の解説（モデル名などを含む）
- Agent 設定の JSON（新規作成時は AgentCore の既定の Agent 設定）

編集と保存の流れは次のとおり。

- 画面には「編集中の設定」を保持する
- 設定変更チャットは Agent との会話とは別に存在する
  - 設定変更チャットの LLM とプロンプトはコードに書き、設定画面からは変更できない
  - 設定変更チャットは Agent 設定画面に置く。PydanticAI で、AgentCore が受け付ける Agent 設定の型どおりの変更案を出させる
  - 送るのは、AgentCore の説明・既定の Agent 設定・編集中の Agent 設定・直近のやり取り・要望
  - やり取りは Agent ごとに保存し、消せる
- 設定変更チャットで変更案ができたら、画面の「編集中の設定」が更新される
  - この時点では DB に保存しない
- 利用者が「保存」したときに、編集中の設定を DB に保存し、利用可能なバージョンにする
- 保存のしかたは、名前を変えたかどうかで分かれる
  - 名前を変えずに保存すると、同じ名前の Agent の新しいバージョンになる
    - 例) FableAgent v1 → FableAgent v2
  - 名前を変えて保存すると、元の Agent はそのままに、同じ AgentCore で名前の異なる Agent を v1 から作る（フォーク）
    - 例) FableAgent v2 を編集して名前を FablePromptCustomed にして保存 → FablePromptCustomed v1
    - 元の Agent のバージョンの履歴と会話は引き継がない。どの Agent のどのバージョンから分かれたかだけを記録し、画面に示す
  - 名前だけを変える（フォークせずに改名する）ことはできない
- Agent 設定は全バージョンを data に残す（docs/specs/実装環境.md）
- Agent 設定を JSON テキストに書き出す道具を tools に置く
  - Agent ごとに一つの JSON（全バージョンの設定を含む）を、既定で data/exports/bot_settings に書き出す（npm run export:bots）

Agent 自身が保存する情報は次のとおり。

- メモリなど、動作上の情報は Agent が自発的に保存するものとして設計する
- 前提情報が大きい場合は、その一部を Agent 自身が保存する
- RAW の保存は、これらに対する保険と位置づける

# 対話履歴 UI

チャットに関するすべての情報を保持し、閲覧できるようにする。調査のために、いつ・どの設定で・何を送り・何が返ったかを後から追えるようにするためである。

## 細則

- 閲覧できる情報は次のとおり
  - 会話履歴
  - 設定値
  - すべての RAW 入力・出力
  - AI 状況（LLM のモデル・バージョンや利用日付などの情報）
- RAW 入力・出力は、RAW 用の DB に保存する
  - 保存するのは LLM API へのリクエストとレスポンスの JSON

チャット履歴の一覧と、会話の継続は次のとおり。

- チャット履歴の一覧は、チャット画面とは別のページに置く
  - 会話ごとに、Agent 名・Agent のバージョン・状態・発言数・最初の発言・開始と最終の日時を示す
  - Agent で絞り込める
- 一覧から会話を開き、そのまま続けられる
- 一覧で、会話ごとの設定値（固定されている Agent のバージョンの中身）を折り畳みで見られる
- エラーで止まった会話は、引き継いだ新しい会話として続ける
  - 同じ Agent のバージョンで新しい会話を作り、エラーより前のやり取りと Agent の状態を写す
  - 応答を得られなかった最後の発言と、エラーは写さない
  - 新しい会話には、引き継ぎ元の会話を記録する
  - 止まった会話そのものは書き換えない（エラーを保存して止める決まりを保つため）
  - Agent が停止している（モデルが存在しない）場合は引き継げない

(決定経緯 : 2026-10-29, docs/decisions/2026-10-29-履歴と複数の秘密.md)
(決定経緯 : 2026-10-29, docs/decisions/2026-10-29-コメントと設定変更チャット.md)

通信時のソースコードのバックアップは次のとおり。

- 通信時の Backend のソースコードを、復元可能な形でバックアップする
  - どういう構造でフローしているかを後から把握できるようにするためである
  - 動作をそのまま再現・復元することは目的としない
  - バックアップの対象は次のとおり
    - Backend の AgentCore のモジュールフォルダ（agents）全体
      - 関連するソースは AgentCore のモジュールフォルダ（agents）に置く（docs/specs/実装環境.md）
      - 自前で書いた AI 機能（PydanticAI を使う側）のコードも含める
      - ライブラリ自体（PydanticAI など）は含めない
      - import をたどって対象を決めることはしない
    - pyproject.toml と uv.lock（ライブラリのバージョンを残すため）
  - バックアップは RAW 用の DB とは別に、data フォルダに ZIP で置く
    - ファイル名は `<ハッシュ>.zip` とする
  - ハッシュは、ファイルのパスと中身から、並び順を固定して計算する
    - ZIP 自体のハッシュは使わない（作成時刻などで変わるため）
    - `__pycache__` などの生成物は含めない
  - ハッシュが既存のものと異なる場合のみ、追加で保存する
  - RAW 用の DB の通信記録には、そのハッシュをキーとして記録する

# エージェント間対話

会話用エージェント（利用者役の Agent）が、利用者の作った Agent と会話し、利用者はそれを見て評価する。Agent を、人の手を介さずに長く話させて調べるためである。会話用エージェントは Agent と同じように組めるが、全く別のものとして扱い、互いに行き来させない。

## 細則

会話用エージェントの扱いは次のとおり。

- 会話用エージェントは、Agent とは別の表・別の AgentCore の登録に置く
  - 会話用エージェントを Agent として会話させてはならない。Agent を会話用エージェントとして使ってもならない
- 管理は Agent と同じとする（名前・AgentCore・JSON の設定、バージョン、フォーク、設定変更チャット、設定の書き出し）
  - 設定の書き出しは、書き出し先の conversation_agents フォルダに置く
- 会話用エージェントは、人間と同じく発言の文だけを出す。表示用の内訳・割込みは出せない

テンプレートの扱いは次のとおり。

- テンプレートは、プロンプトに埋め込む名前付きの文章（台本など）。名前は作成後に変えられない
  - 名前に `{` `}` と改行は使えない
- 保存するたびに新しいバージョンになる
- 保存するときにサニタイズする。改行を LF にそろえ、改行とタブ以外の制御文字を取り除く
- 埋め込めるのは、現状は会話用エージェントの設定だけ。設定の中に `{{template:名前}}` と書く
  - 置き換えは一度だけ行い、入れ子にはしない
- エージェント間対話を始めたときの最新バージョンに固定する。後からテンプレートを直しても、始めた対話は変わらない
  - 設定にあるテンプレートが無ければ、対話を始められない

エージェント間対話の進め方は次のとおり。

- 会話用エージェントと Agent を選んで対話を始める。両者は開始時のバージョンに固定する
- 1 ターンは、会話用エージェントの発言と、それへの Agent の応答の一組
  - Agent は、会話用エージェントの発言を利用者の発言として受け取る。割込み要求は渡さない
- 「次の発言を行う」で 1 ターン進める。「自動で進める」で指定したターン数（1〜50）を続けて進める
  - 自動で進めている途中で、そのターンで止められる
  - 50 ターンの上限は画面で守る。API は 1 ターンずつしか進めない
- エラーが起きたら、エラーを保存して止める。引き継いで続けるときは、同じバージョン（テンプレートを含む）で新しい対話を作る
  - Agent の応答を得られなかった会話用エージェントの発言とエラーは引き継がない
- 会話用エージェント・Agent のどちらの発言にも、評価とコメントを一つずつ付けられる。対話全体へのコメントも付けられる
  - 評価・コメントの決まりは、チャット UI と同じ
- RAW パラメーター欄は、チャット UI と同じように使える。RAW は発言ごとに一つ記録する
- エージェント間対話の記録は、Agent との会話とは別の表に置く。チャット履歴には出さない
- 履歴の一覧は別のページに置き、会話用エージェントと Agent で絞り込める。両者の設定値とテンプレートの中身を折り畳みで見られる

# 並行会話

会話の最初から、または会話・エージェント間対話の途中から、同じ利用者の入力に対する Agent の応答（候補）を何パターンも作って見比べ、一つを採用して新しい会話として続ける。シミュレータとは別の機能で、Agent の応答のばらつきを並べて調べるためである。元の会話は変えず、採用して分岐したものをたどるときに元の会話へ戻らずに済むよう、分かれる位置までの会話を写して持つ。

## 細則

始め方と写し方は次のとおり。

- チャットの会話・エージェント間対話の、Agent の発言にある「ここから並行会話」で始める。その発言までを写した並行会話を作り、並行会話の画面に移る
  - 利用者の発言からは始められない
- 並行会話の画面で Agent を選び「新しい会話を並行会話」で、会話の最初から始めることもできる。写す発言は無く、Agent はその時点の最新のバージョンに固定する
- 写すのは、発言の本文・表示用の内訳・RAW の記録・Agent の状態・日時。分かれる位置の Agent の状態から続ける
- エージェント間対話から写すときは、会話用エージェントの発言を利用者の発言として写す。以後は利用者が入力する。会話用エージェントは呼ばない
- 同じ位置から何度でも並行会話を作れ、どれも残る
- 並行会話の画面からは、元の会話・対話へは戻らない

(決定経緯 : 2026-10-31, docs/decisions/2026-10-31-並行会話の最初から.md)

候補の作り方は次のとおり。

- 利用者の入力と、パターン数（既定 10、1〜50）を指定して、候補を作る。これを 1 回とする
- 入力の言い回しを変えて、同じ並行会話で何回でも候補を作れる。回は積み上がって残る
- 候補は裏で作り、画面は作り終わるまで読み直して、できたものから表示する
- 同時に作る数は、並行会話設定の concurrency（既定 3、1〜20）。API の提供元ごとの同時実行の制限は扱わない
- 候補の表示はチャット画面と同じ（表示用の内訳・シミュレータの実行記録へのリンク・RAW パラメーター欄）
- 割込み要求は、候補に伝えない
  - (※ 現状、割込みを使う必要が出たら、分かれる位置で伝えていない割込み要求をすべての候補に伝える形を想定している)

採用と記録は次のとおり。

- 応答を作れた候補を採用すると、写した発言・その回の入力・候補の応答を持つ新しい会話を作り、チャット画面に移る。以後は普通の会話として続ける
- 同じ候補を何度でも採用でき、そのたびに新しい会話になる。採用した会話は候補ごとに一覧で示す
- 採用した会話には、どの並行会話の候補から作ったかを記録し、チャット画面からその並行会話へ移れる
- 並行会話の記録（写した発言・回・すべての候補）は、会話の記録とは別の表に置く。採用しなかった候補も残す
- 候補を作る中で呼んだシミュレータの実行記録は、候補に結びつけて残す（呼び出し元は「並行会話の候補」）
- 会話をまたぐ記録（docs/specs/AgentCore一覧.md）は、候補を採用したときにだけ書く

(決定経緯 : 2026-10-31, docs/decisions/2026-10-31-並行会話.md)
