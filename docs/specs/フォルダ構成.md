フォルダ構成
============

# 概要

本資料は、リポジトリのルート直下と docs 配下のフォルダ構成を定める。

## 全体像

- ルート直下には apps / tools / docs を置く
- 確定済みの事項は docs 配下の specs / knowhows / decisions に保管する
- フォルダ構成についての規約（本資料）は docs/specs に置く
- 作業指示・作業記録は worknote に置く（規約は .claude/rules/worknote_folder.md）
  - (※ 現状、apps / tools の用途と、specs / knowhows / decisions の振り分け基準は未定。worknote/taskcards/TC0001-フォルダ用途の定義.md で扱う)


# 作業手順

1. 置こうとしている内容が確定済みかを判断する
2. 確定済みなら docs 配下の specs / knowhows / decisions のいずれかに置く
3. 未決・作業中なら worknote 配下に置く（未決事項は taskcards に置く）


# ルート直下の配置

ルート直下には apps / tools / docs を置く。置き場所を固定しておくことで、成果物と資料がどこにあるかを迷わないようにするためである。

## 細則

- ルート直下に置くフォルダは次のとおり
  - apps
  - tools
  - docs
  - worknote（作業用。.claude/rules/worknote_folder.md で定める）
- 中身がまだ無いフォルダは .gitkeep を置いて保持する

(決定経緯 : 2026-10-29, worknote/worklog/0001-2026-10-29-仕様書・フォルダ確認.md)


# 確定事項の保管（docs）

確定済みの事項は docs 配下に保管する。確定したものと検討中のものを混ぜず、docs を見れば確定事項だけが分かる状態を保つためである。

## 細則

- docs 配下には次のフォルダを置く
  - specs
  - knowhows
  - decisions
- フォルダ構成の規約（本資料）は docs/specs に置く
- 未決・検討中の事項は docs に置いてはならない（worknote/taskcards に置く）

(決定経緯 : 2026-10-29, worknote/worklog/0001-2026-10-29-仕様書・フォルダ確認.md)
